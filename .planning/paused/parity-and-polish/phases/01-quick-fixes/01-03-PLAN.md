<objective>
Two known macOS bugs, both isolated to two files:

1. D-01 — `mixAudioFiles()` in RecordingViewModel currently averages the two sources (`(micSample + sysSample) * 0.5`), which halves the perceived volume of a single active speaker. It must take the element-wise max of the two PCM sample arrays so combined recordings reflect the louder of the two sources at any instant (matching the waveform-merge logic already used at the top of the same file, which uses `max(mic[i], sys[i])`).
2. D-02 — `SystemAudioCapture.startDurationTimer()` wraps its 1s tick body in `Task { @MainActor in ... }`, which hops actors unnecessarily and trips Swift 6 concurrency diagnostics. Since the `Timer.scheduledTimer` callback already runs on the main run loop, it should use `MainActor.assumeIsolated` to access `@MainActor` state synchronously without a Task hop.

Purpose: Fix documented bugs D-01 and D-02 (CLAUDE.md Gotchas references both).
Output: combined audio = element-wise max; timer = MainActor.assumeIsolated, no new concurrency warnings.
</objective>
