## FINDINGS.md Document Contract

This is the operative design contract for Phase 2. Source: `02-CONTEXT.md` decisions D-11 through D-16.

### File

| Property | Value |
|----------|-------|
| Filename | `FINDINGS.md` |
| Location | `.planning/phases/02-ux-review/FINDINGS.md` |
| Format | Single markdown table + optional detail sections |
| Source of truth | Yes — Phase 4 plans reference FND-IDs, never duplicate rows |

### Required Header (verbatim)

```markdown
# Phase 2 UX Review Findings
Scope:
- Platforms: macOS, Windows
- Flows: opname start/stop, transcript-lijst, notule-weergave, instellingen, auth
- Framework: Nielsen + Apple HIG / Microsoft Fluent
- Prioritering: severity × frequentie + parity-boost
```

### Table Columns (fixed, in order)

| Column | Allowed Values |
|--------|---------------|
| ID | `FND-001`, `FND-002`, … — never renumber once assigned |
| Prio | `P1` / `P2` / `P3` |
| Platform | `macOS` / `Windows` / `Beide` |
| Flow | `Opname start/stop` / `Transcript-lijst` / `Notule-weergave` / `Instellingen` / `Auth` |
| Titel | Short Dutch description of the finding |
| Heuristiek / richtlijn | Nielsen heuristic name, Apple HIG ref, or Fluent 2 ref |
| Severity | `Blokkerend` / `Hinderend` / `Cosmetisch` |
| Frequentie | `Hoog` / `Middel` / `Laag` |
| Parity | `Ja` / `Nee` / `N.v.t.` |
| Impact | One-line Dutch description of user impact |
| Fix-hint | Concrete short recommendation |
| Evidence | Screenshot ref, screen name, or timestamp |

### Priority Rubric

**Base priority (task impact):**
- `P1 — Kritiek:` blocks or undermines a core flow (silent failure, unreliable status, no recovery route, data loss or false perception of save/record)
- `P2 — Belangrijk:` task completes but with clear friction, uncertainty, or workaround needed
- `P3 — Verbetering/polish:` minor usability, copy, visual, or convention issue without material hindrance

**Frequency modifier:** raise one level for high-frequency/central actions (e.g. record start/stop); lower one level for edge cases or rarely-used settings.

**Parity boost:** raise one level when a macOS↔Windows difference affects the milestone goal — behavior, status feedback, terminology, navigation, flow order, recovery paths, or findability of the same feature. Do NOT boost for purely visual/cosmetic platform-native differences.

**Effort excluded:** effort estimation belongs in Phase 4, not here.

### Optional Detail Sections

For complex P1/P2 items only, add a block after the table:

```markdown
### FND-XXX — {Titel}

**Observatie:** {wat is er te zien/ervaren}
**Impact:** {wat betekent dit voor de gebruiker}
**Aanbeveling:** {concrete actie}
**Evidence:** {screenshot, scherm-aanduiding, of timestamp}
```

### Example Row (format anchor from CONTEXT.md)

```
| FND-001 | P1 | Beide | Opname start/stop | Opnamestatus is onvoldoende expliciet na starten | Visibility of system status | Blokkerend | Hoog | Nee | Gebruiker weet niet zeker of opname actief is | Maak actieve opname persistent zichtbaar met label + indicator + duidelijke stop-actie | screenshot/schermref |
```
